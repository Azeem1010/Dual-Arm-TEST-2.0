# home_A / home_C 姿態換算

目前第 17 版韌體來源的設定如下；若實際控制板刷入不同版本，需以 `GET_HOME` 回覆為準。

| 手臂 | 名稱 | j1 / j2 / j3 / j4 馬達 ID | HOME 原始位置值 |
|---|---|---|---|
| Arm 1 | home_A | 17 / 3 / 2 / 15 | 90 / 567 / 712 / 825 |
| Arm 2 | home_C | 12 / 1 / 8 / 16 | 590 / 567 / 712 / 825 |

每軸使用下式換算，再透過目前 CAD 運動鏈做正向運動學：

```text
q_rad = direction × (HOME_raw − raw_at_cad_zero) × (300° / 1023) × π / 180
```

`raw_at_cad_zero` 是該軸處於 CAD q=0 時的馬達位置值；`direction` 為馬達數字增加時是否沿 URDF 正方向轉動（+1 或 −1）。馬達運動範圍與約 0.29° 解析度依據 [ROBOTIS AX-12A 文件](https://emanual.robotis.com/docs/en/dxl/ax/ax-12a/)；安裝角、舵盤偏置與方向無法由數字解析度推得。

僅以 512 作算術參考，兩組數字對應的軸角差是：

| 名稱 | j1 | j2 | j3 | j4 |
|---|---:|---:|---:|---:|
| home_A | −123.754° | 16.129° | 58.651° | 91.789° |
| home_C | 22.874° | 16.129° | 58.651° | 91.789° |

**這張表不是手臂的 URDF 角度，也不是已確認的預備姿態。** 例如直接把 Arm 1 的 −123.754° 套在目前 ±1.5 rad 模擬底座限位就會超限；不能靠放寬限位或自訂偏置假裝校正完成。

使用者已同意先使用明確標示的模擬假設。設定檔為 `src/dual_arm_coordinator/config/sim/runtime.json`，`mapping_mode=simulation_assumed`、`hardware_use_allowed=false`，實機校正仍為 NOT_RUN。

2026-11-09 使用者提供實機零姿態：**四顆馬達 raw 都是 512、手臂伸直**（此處理解為垂直朝上）。CAD q=0 不是這個姿勢，垂直朝上對應 q=(0, −35, −55, 0)°，所以 `raw_at_cad_zero` 不是全部填 512。

| 名稱 | CAD 零位 raw（j1..j4） | 方向（推論） | 換算後關節角 | TCP（mm） |
|---|---|---|---|---|
| home_A | **192.3（暫定）** / 631.35 / 699.55 / 512 | **−1** / +1 / +1 / +1 | +30° / −18.87° / 3.65° / 91.79° | (166.3, −27.7, 140.8) |
| home_C | 512 / 631.35 / 699.55 / 512 | **−1** / +1 / +1 / +1 | −22.87° / −18.87° / 3.65° / 91.79° | (−151.6, −35.0, 140.8) |

2026-11-09 模擬改為手臂在遠離使用者側、A 區在手臂左邊（見 [COORDINATE_FRAMES.md](COORDINATE_FRAMES.md)），所以兩支手臂 j1 的模擬方向改為 −1。這是配合配置的推論，實際馬達方向尚未量測。

吸盤軸離垂直向下 13.4°。方向是由姿勢合理性推論，尚未實際轉動馬達確認。腕關節上限只在模擬中由 1.5 放寬到 1.65 rad，讓 raw 825 落在限位內；實機是否會干涉未驗證。

**Arm 1 底座尚未解決：** 使用者確認 Arm 1 在 raw 512 時朝 +Y，且實機 home_A 朝 A 區；但 raw 90 相對 512 是 123.75°，而模擬中 A 區只需約 19°～41°，兩者矛盾。此外目前模擬的手臂面向 −Y，要確認當時說的 +Y 是哪個座標系。192.3 是維持 30° 轉向 A 區的模擬暫定值。請在扭力關閉時，用第 17 版 `manual_position_terminal.py` 依序取得 `GET_HOME,arm1`、底座正對 +Y 時的 `READ,arm1`、實機 home_A 姿勢的 `READ,arm1`，再替換此值。

不能將此假設複製到硬體設定；量測完成後需替換零位與方向，重新計算並驗證。重算指令：

```bash
python3 scripts/report_home_poses.py
```

報告 `docs/evidence/home_poses.json` 會輸出關節 rad、TCP 4×4 姿態矩陣及是否在目前限位內。還需另做碰撞與路徑驗證。

新版取放程式的開始與回程已接到這個 HOME 換算；缺資料時會在第一個動作之前停止，提示 `home_A` 或 `home_C` 缺值。CAD 零位僅是模型載入基準，不能再當成 HOME。舊版展示的零位回程記錄留在 `docs/evidence/before_revision_20261109/`，不代表本版 HOME 已驗收。
